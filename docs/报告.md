## 为什么改这些代码

1. 正文原字库没有足够汉字。新增小、中、大三档字模，缺字从固定版本的开源字体生成；标题描边字体只收录实际用到的汉字，减少 ROM 占用。
2. 小号字体原先把高分辨率字形的像素作 OR 合并，复杂字如“蹑”会糊成白块。现在优先选更合适的 12px 字源并用点采样；“蹑”另有保留左右空列的 9×9 手工字模。
3. 字形多于 255 个后，旧的 8 位缓存编号会重复，可能显示错字。描边字库改用稀疏码点表和较宽的缓存键。
4. 英文按空格折行，中文常无空格，因此正文排版器增加中文标点禁则。源代码里相邻的引号会被 C 编译器拼成一个字符串；只有字符串内部的反斜杠 n 才是画面换行。中文和英文宽度不同，句中换行无需逐字相同，但必须适配文本框。
5. 译文导入器现在仅导入阶段 5，保留草稿供审校。咖啡馆原版用于垂直排版的首尾空行已恢复；七条较长译文重新断行，关卡说明的多余空行也已去掉。注释说明了文件级改动，未校对的源码条目带 TODO 未校对。
6. 完美挑战奖励通知原先混用英文，还使用固定 45 字节 memcpy 加多次 strcat。现在用译文包中的已校对片段组成中文句子，并按 0x100 字节缓冲区容量写入。整句语气和实机折行仍标 TODO 未校对。
