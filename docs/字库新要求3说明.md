# 字库新要求3：做法与验收

日期：2026-10-26；分支：`font/text-localization`。

本轮先同步了远程更新到 `684e5744`，再按《一些新要求3.md》和用户提供的华康字体、阴影示例修改。远程重写历史中的上一轮提交已按相同内容对齐，旧本地状态另保存在 `backup/font-before-requirements3-20261026`。

## 要求与结果

| 要求 | 当前实现 |
| --- | --- |
| 重新统计 CJK，生成 small 和 large | 扫描当前源码的字符串字面量，得到 1,290 个 CJK 字符、21 个全角字符，加上占位方框共 1,312 个。两套字库使用同一份新清单重新生成。 |
| 内部阴影按照示例 | 校验示例图片散列，提取字身底部三行的主要色阶：最底行9、前两行10、上部11；描边为8。阴影完全留在字身内。极短标点保留顶部亮色。 |
| large 改用华康方圆体W7，字号16 | 使用用户原始 TTF，以16px单色栅格化。按用户随后确认的取舍，先把超界字身等比例缩小到最多13×14，再向右加粗1px并加一圈描边，保留16×16字格。 |
| 其余同上次 | small仍用Fusion Bold Pixel 12px；描边后的左边界x=0、底边界y=15，字距与实际描边宽度一致。 |

用户对字号和字格冲突的确认原文：**“保持 16×16 字格，允许缩小字身后描边”**。因此这里的16px是源字体栅格化字号，超界汉字的最终字身会缩小；没有把17px以上的字模直接裁成16px。

## 字符为什么要重新统计

上一版把旧译文归档与上次字表一起合并，新上传的源码文字可能没有进入字库，删掉的旧字符也会一直保留。现在每次生成都重新读取 `asm/audio/data/games/graphics/include/src` 下 `.c/.h/.s/.bs` 的字符串，覆盖各条件编译分支；注释、旧归档和上一次清单不参与默认统计。

新纳入：**乓、庞、捣、英**。不再需要的24字：及腹饱０４５９ＧＩＰＱＲＴＶＷｅｈｉｌｍｒｓｕｘ。与上一版相比，字形总数从1,332变为1,312，每套字库167,936字节。

`tools/font/outline_chars.txt` 保存本次结果，方便搜索；它不再是默认生成输入。`build/font_report/outline.usage.json` 可以查每个字符来自哪些源码文件。新统计摘要见 `qa/font3-charset-audit.json`。

## 字源与阴影

- large：`华康方圆体w7.ttf`，字体内部名称 `DFPFangYuanW7-GB`，用户文件SHA-256：`ab7b94672ba0e8d1cb4e572a6a3bbe7c4b2d636610af202289d48e42b9ea090c`。
- small：固定版本Fusion Bold Pixel 12px，版本2026.10.16。
- 示例原图保存为 `tools/font/supplied/shading_example.png`。生成器校验其散列并读取主色阶，样式不再按每一条笔画的下沿逐点变暗。
- 大号1,280字来自华康，其中67字原本就能放下、1,213字经适配后加粗；32个字源缺字沿用Unifont回退。小号1,311字来自粗像素12px，仅“骜”回退。清单见 `build/font_report/outline.report.txt`。

字体来源和适配上限写在 `tools/font/font_sources.json`。原始TTF在本地保存，生成后的点阵提交到仓库。

## 重建命令

```powershell
python -m pip install -r tools/font/requirements.txt
python tools/font/fetch_fonts.py --large-font "D:/Luna/Downloads/华康方圆体w7.ttf"
python tools/font/build_outline_font.py
python tools/font/test_tengoku_font.py
```

生成时保持单色像素，缩小时使用确定的整数最近邻采样。描边和加粗后超出字格会报错。输出仍在 `graphics/font/outline/{small,large}/`，索引和字宽同步写入 `data/font_definitions.c`。
