# 《一些新要求2》字库说明与验收

日期：2026-10-24；分支：`font/text-localization`。

本轮按用户提供的《一些新要求2.md》和《方正像素14.TTF》修改标题汉字及全角标点的生成规则。

| 用户要求 | 实现与证据 |
| --- | --- |
| 只描边，阴影只加在字身内 | 给字身加一圈 1px 描边；原先描边下面额外多出的一行投影已去除。每条笔画的下沿使用较深字身色，阴影占据的仍是原字身点。全部交付字形验证只有透明、描边、字身和内部阴影四种颜色。 |
| 描边后贴左下 | 每个非空字模的最左像素是 x=0、最下像素是 y=15。只去除源字体透明留白，不缩放，也不裁掉笔画；超过 16×16 会报错。全部 2,664 个字模逐个验证。 |
| small 使用 Fusion Bold Pixel 12px | 固定 2026.10.16 的 12px 比例 BDF，保留完整原始点阵。1,331 字直接来自此字源；仅“骜”缺字而回退 Unifont。“蹑”直接使用新字源。 |
| large 使用方正像素14，并自动加粗 | 使用用户提供的 FZXS14 原 TTF，以 14px 单色输出，再向右扩展 1px 加粗，然后描边；不改变原字形高度。1,300 字来自方正，缺少的 32 个字回退 Unifont。 |

## 为什么字距也改了

原小号标题的字距参数是 -1。新字身加描边后通常宽 14px，若继续用旧步进，两个字会压到彼此的描边。因此每字步进以实际描边宽度计算，小号额外补 1px 抵消原版 -1 参数；大号直接使用实际宽度。文本内容和节拍控制码不需要随字体改写。

## 现在字体从哪里来

- 小号官方发布包：<https://github.com/pixel-font-studio/fusion-bold-pixel-font/releases/download/2026.10.16/fusion-bold-pixel-font-12px-proportional-bdf-v2026.10.16.zip>；SHA-256 `567c912ccd9bbcc7cac42ddff309616262db4dca898886f6436ea6f18ef43036`。
- 大号：用户提供的《方正像素14.TTF》；SHA-256 `c1bfb94df96b5e907a0a07c87ab79d50703bd887c0d953e75aa2ea8620e25193`。原 TTF 保存在本地 `tools/font/third_party/fangzheng-pixel-14.ttf`，仓库保存来源信息及生成字模。
- 字源信息集中在 `tools/font/font_sources.json`；字符清单在 `tools/font/outline_chars.txt`，可以直接搜索某个汉字。清单加入仓库后，重建不再依赖 build 临时目录中的字符文件。
- 仍使用每字 16×16、4bpp、128 字节的数据格式，游戏运行时按 Unicode 查找字模，再复制到显存。

32 个方正缺字：冨剣勝宮寛時東樹橋湯澤穂竜紀総義聡葉薫貴賀輔輝辺達郷鈴鎌飯髙黒龍。它们主要出现在名字或日文汉字中，回退清单也由生成器写到 `build/font_report/outline.report.txt`。

## 如何重建

在项目根目录执行。字体路径可以换成你电脑上的实际路径：

```powershell
python -m pip install -r tools/font/requirements.txt
python tools/font/fetch_fonts.py --large-font "D:/Luna/Downloads/方正像素14.TTF"
python tools/font/build_outline_font.py
python tools/font/test_tengoku_font.py
```

本次使用 Pillow 12.3.0、FreeType 2.14.3、fonttools 4.67.0；依赖版本已记录。输出仍在 `graphics/font/outline/{small,large}/`，字符索引及字宽同步更新 `data/font_definitions.c`。

## 验证结果

- 55 份正文点阵往返检查通过。
- 2,664 个描边字模逐个检查左下边界、完整描边、内部阴影和字宽；所有有指定字源的字模逐点比对，确认 small 不缩放、large 确实加粗一个像素。
- mGBA 中分别跑完整首盆舞①和盆舞②。共 988 次歌词对象观察，最大宽度均为 153px，零次超出 240px 画面；颜色和高亮沿用原版节奏脚本。见 `font2-odori.png`、`font2-dance.png`、`font2-metrics.json`。
- 实际关卡选择界面的“蹑鼠蹑脚”见 `font2-rat-race.png`；放大点阵示例见 `font2-glyphs.png`。

测试构建沿用此前已经按源内容比对的压缩图形缓存；原版 baserom.gba 仍不在已查目录，所以这不是标准 Makefile 从零构建的证明。该限制与本轮标题字体的生成、字节核对和运行检查分别记录。
